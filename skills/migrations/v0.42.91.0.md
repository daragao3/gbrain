# v0.42.91.0 — push remote resolved from config

Every gbrain push used to target `origin` by name. In a checkout copied from
another project, `origin` is that other project and the user's own copy sits
under a different remote name, so gbrain pushed the user's work to a repository
they do not own. Three paths did this: the brain-repo durability push, the
push-probe that precedes it, and `skillpack endorse --push`.

gbrain now resolves the remote the way git does — `branch.<b>.pushRemote`,
`remote.pushDefault`, `branch.<b>.remote`, the trunk's remote, a sole remote,
then `origin` only when the repository has one — and refuses rather than
guessing when nothing resolves.

## No schema migration

Nothing to apply. There is no DDL in this release.

## What the agent should do after upgrading

1. **Re-harden every brain repo that was hardened before this release.** The
   push-retry logic is baked into two generated files at harden time
   (`scripts/brain-commit-push.sh`, committed, and `.git/hooks/post-commit`,
   local and untracked). An existing repo keeps the old `git push origin` copies
   until they are regenerated. Hardening is idempotent:

   ```bash
   gbrain sources harden --all
   ```

   If the sources span multiple hosts or accounts, harden them one at a time
   with their own `--pat-file`; `--all` refuses one PAT across several hosts.

2. **Confirm each brain repo names the remote its work belongs to.** Only needed
   for a repo with more than one remote:

   ```bash
   git -C <repo> remote
   git -C <repo> config --get branch.main.remote
   ```

   If the second command prints nothing and `origin` is not the right target,
   name the right one once:

   ```bash
   git -C <repo> config remote.pushDefault <your-remote-name>
   ```

3. **Check the harden report.** Its closing line now reads `clean against push
   remote`, and the verify step names the remote it confirmed access against. A
   repo with no remote at all is reported as `needs_attention` with reason
   `no_remote` instead of failing partway through a push.

## What does NOT change

Fetching. `gbrain sources pull` and the durability cron still read from
`origin`. This release covers where commits go, not where updates come from.
